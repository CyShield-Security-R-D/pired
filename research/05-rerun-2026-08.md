# DVBank re-run, August 2026

*The published numbers reproduce. What they measure is not what was claimed.*

## Why re-run

`research/03` and `research/04` describe a harness that no longer exists. Between
that run and this one, Assay found and fixed three defects in the recording path:
the coverage dependency was never stated in the prompt, the evidence contract was
unfulfillable (findings were asked to cite paths no tool could create), and the
bulk-refutation path discarded any list a model serialized as a string.

## Method

Faithful to `02-benchmark-methodology.md`: isolated target (the de-leaked
`clean/` tree plus the six decoys, nothing else), the original detection prompt
verbatim, the official grader at `window=3`. A leakage audit refuses to run if a
banned file appears under the target; it found none.

Applying the corrections `04 §7b` asked for: raw **and** backend-scoped precision,
findings de-duplicated before grading, **n=5** with the spread, and — new — the
**ledger graded alongside the emitted report**, which asks whether the harness
recorded what it claimed.

Validated before spending model time: feeding the answer key back through the
pipeline reproduces P/R/F1 = 1.0.

## Results (n=5, qwen3.8-27b via OpenRouter)

| view | recall | precision | F1 |
|---|---|---|---|
| emitted report, raw | **0.743** [0.698, 0.792] | 0.646 [0.569, 0.714] | 0.690 [0.627, 0.734] |
| emitted report, backend-scoped | **0.743** [0.698, 0.792] | 0.734 [0.661, 0.816] | **0.737** [0.679, 0.784] |
| pired ledger | 0.011 [0.000, 0.057] | 0.150 | 0.021 |

Findings per run: **61.4** emitted [54, 70] · **0.8** recorded in the ledger [0, 4].

## 1. The detection result replicates

Published recall 0.736, precision 0.629, F1 0.678. Re-run recall 0.743,
precision 0.646, F1 0.690 — every published figure sits inside the re-run's
range. That is a clean replication at n=5 against a single-run original, and it
holds after de-duplication, which the audit expected to cost the noisier arm
something.

Backend-scoped F1 of 0.737 also confirms the audit's estimate that the gap to
codex (0.735) closes to a tie once the arms are no longer penalised for finding
real frontend bugs the key cannot score.

## 2. The ledger was not used at all

`findings.jsonl` does not exist for four of the five runs. `hypotheses.jsonl` and
`inventory.jsonl` exist for none of them. The agent wrote 54-70 findings to
`findings.json` — as the prompt instructs — and called `record` almost never.

This is not a recording defect of the kind Assay fixed earlier. The prompt asks
for a JSON file, the model produces a JSON file, and the entire engagement
apparatus is bypassed.

## 3. What that means for the published conclusion

`04 §6` states:

> The **record/recall engagement workflow** is not ceremony — it measurably
> improved coverage over an unstructured review of the same model.

The benchmark cannot support that claim. Arm A and arm C differed in system
prompt *and* tool availability, but the tools were not exercised: the ledger is
empty. Whatever lifted recall from 0.585 to 0.736, it was not the record/recall
workflow, because the workflow did not run.

The defensible version is narrower and still substantial: **a security-tuned
system prompt lifted a 27B model from F1 0.574 to 0.690**, which remains the
central finding and remains cheap. The claim that the *harness machinery* did it
is unsupported by this experiment.

This is not evidence that the ledger is worthless — it is evidence that this
benchmark never tested it. A one-shot detection scan is the task least likely to
benefit from durable cross-session state. The compounding experiment (three arms,
k sessions, persisted vs wiped ledger) is the experiment that would settle it,
and it has not been run.

## 4. Threats to validity

- One target, one model, one provider. The instrumentation work found that the
  same nominal model behaves differently across providers; this run is OpenRouter
  only.
- The ledger view is scored by extracting `file:line` from recorded findings.
  With four of five ledgers empty, the extraction is barely exercised — the
  finding rests on the files not existing, not on the extraction being right.
- No mutation-variant control in this run; contamination is unchanged from the
  original analysis.
