# ADR draft (3.2) — The budget is stated as a ceiling, coverage as areas, and a session settles into the ledger

**Status:** draft · 2026-09-26 · Phase 3 item 3.2 of `docs/delegation-v6-plan.md` · design in
`docs/delegation-v6-phase3-design.md` §3.2 · amends ADR-030 (stop precedence) · built on branch
`p3b/budget`; nothing merges to `main` until the Phase 4 trial passes

### Context

- **Luna stops early, in both arms** (`research/12-delegation-trial-2026-09.md`). About 40% of
  Luna runs end within 5 minutes. 32 of 41 baseline and 31 of 37 candidate Luna runs end by saying
  the review is incomplete and offering to continue; unattended, the run simply ends. GLM and
  DeepSeek never stop early.
- **Stopping early has not been shown to cost true positives.** Short Luna runs averaged 0.50 TP
  per run against 0.32 for longer ones, but the short runs fell on the easier targets.
- **Spend does not visibly buy findings.** True positives per run are roughly flat across token
  buckets: Luna baseline 0.44–0.67 from under 2M to 25M tokens. This is observational; only a
  randomised cap would give a dose-response answer. Meanwhile the v4 candidate's pass-mean tokens
  rose 27.0M → 43.8M, +62% (ADR-026, *Outcome*).
- **The literature research/12 cites** says agents under-use a budget they cannot see (showing
  used and remaining each turn gave the same accuracy at 31% lower cost, BATS), and that
  context-aware models wrap up early unless told their state persists.
- **pired's own prompt may feed the closings.** `methodologyBlock` ended "Before finishing, briefly
  note what you did not get to and would investigate with more time." It asks every run, in both
  arms, for exactly the paragraph the text test reads as an offer. Its contribution is not measured.
- **The stop classifier (ADR-030) can only read prose.** A run that is finished and a run that
  hands back read alike unless the closing's grammar differs, and the rule's error rate is not yet
  measured per arm.

### Decision

- **A budget, stated only where one exists.** The scope's optional
  `budget: {tokens?, minutes?, deadline?}` (per session, like `maxAgents`) is read by
  `parseBudget`. Absent, nothing changes: no line.
  - Tokens count every call the session pays for: the lead's turns (`turn_end` usage), its workers
    and verifiers (pi-subagents' per-child `usage` on the `subagent` tool's end, once per call id)
    and the scribe's own `complete()` calls. Workers are foreground only: pired's gate refuses
    async launches, so none finishes outside that event.
  - Minutes are wall clock from `session_start`, or, when `deadline` (an absolute ISO time) is
    set, the ceiling less the minutes left before it, so the count follows the clock that stops
    the session.
  - Turns are not a unit: nobody buys turns, and a turn's cost varies with context size.
- **One line, in the tail block, every request.** `renderBudgetLine` states used and left: "Budget:
  12 of 45 min used, 33 left · 6.1M of 20M tokens used, 13.9M left." Either unit may be absent;
  minutes used round up and left is the rest. It sits in the `<pired-coverage>` block the
  `context` handler rebuilds after the cached prefix, never in the system prompt, where a number
  that moves every request would break the prompt cache. Under 80% it is the numbers alone. From
  80% of the most-used ceiling it adds "— a ceiling, not a target. N% is used: record what is
  established."; at the ceiling, "— a ceiling, not a target. The ceiling is reached: settle
  (`record kind=settle`), which records what remains for the next session.", or, when the lead's
  last settle has had no work after it, "— a ceiling, not a target. The ceiling is reached;
  settled: <outcome>." `recall status` repeats it. pired enforces nothing; the ceiling is stated.
- **Coverage as areas** (`core/areas.ts`, pure, derived, never stored). Surface is grouped by the
  directory of its `file`, else by host, else into one "no file or host" area. Past 20
  directories, every directory is cut to the deepest depth that fits, so every element stays
  counted. Each area's status comes from its cells (`untested`, `in progress`, `settled`,
  `blocked`) with a finding count. Listed source directories with no recorded surface in or below
  them are *unmapped*, outermost only, and only once some surface names a file in the tree. A file
  outside the source root gets an area of its own and marks nothing mapped. The listing is taken by
  `extensions/lib/source-dirs.ts` — directory-only, bounded by depth (4) and count (400), skipping
  hidden, dependency, build and runtime-state directories — and only for a source-only engagement
  or once a `file` is recorded: on a live target the cwd is only where the shell started, and its
  folder names (other clients' among them) would reach the provider every request. The tail
  block carries a bounded line (settled areas
  counted, the rest named in path order up to 8, "+N more" stated, nothing before any surface is
  recorded); the settle reply lists them in full; `recall status` lists up to 20. It ranks nothing.
- **An explicit settle.** `record kind=settle outcome=finished|paused|blocked note="…"` appends a
  `SettleRecord` to `sessions.jsonl`.
  - Only the outcome and the note are the caller's. The remainder — open cells, unmapped areas,
    unchallenged findings keyed by the `by` that created them, inconclusive hypotheses, open
    blockers, budget spent — is computed by `core/settle.ts` from the ledger. A remainder sent with
    the call is never read, and the reply says so.
  - It never refuses on what remains. The reply lists the remainder and the areas and says that
    settling does not end the session.
  - A settle is history: never updated, never deleted.
  - Only the lead settles. The record tool refuses `kind=settle` from any author but `lead`
    (a worker, the scribe, the operator's CLI, an unnamed caller), which holds whichever of it and
    3.1's refusal in `core/child.ts` merges first. Every reader takes the lead's newest settle only.
  - The widened `outcome` enum would let a settle word through on a hypothesis, where it used to
    be dropped silently; that is now refused with the hypothesis outcomes named.
- **The prompt says the state persists** (static, in the cached prefix; every change is listed
  below).
- **The stop classifier reads the settle (amends ADR-030).** Precedence becomes error, budget, turn
  cap, **settle**, text test.
  - `finished` → finished; `paused` or `blocked` → offered-to-continue (budget is left, or the
    budget rule would have fired).
  - A settle followed by a ledger write by anyone but `scribe` or `operator` (created or updated
    after it) is superseded, and the text test decides. The scribe transcribes review the lead
    already wrote and the operator answers from outside, so neither is the session working on.
    This reads the row's creator `by`, which updates keep; there is no `updatedBy`, so a scribe's
    update to a lead-created row counts as work. The benchmark runs the scribe off.
  - Whenever a settle is read the text test still runs; its result is in `evidence` and in
    `textTest`.
  - **The summary's headline counts the text test in both arms** (`textTest.outcome ?? outcome`):
    only the candidate can settle, so counting the settle-decided outcome would compare two
    instruments. Settles are tallied per arm apart (finished, paused, blocked, superseded, none).
  - **An arm-neutral stopping measure, co-primary with the text test.** Each run's `stop` carries
    `timeShare`, the share of the time limit used at the stop (from the process's own start and
    end), and `leftWithOpenWork`: it stopped on its own with time left while the ledger held open
    hypotheses or open cells (`engagementTelemetry` now carries `openCells`). The summary gives, per
    arm, the median time share and the count of judged runs that left with open work. Neither
    reads prose or a settle.
  - `engagementTelemetry` carries `lastSettle` (outcome, time, note, author, remainder,
    `laterWrites`); the run record's `stop` carries the settle beside the cross-check.
- **The harness states only what it enforces, to the candidate only.** `reviewScope` writes
  `budget: { minutes, deadline }` into the candidate arm's scope: `minutes` is the run's time limit
  rounded down, and `deadline` the time it runs out, computed before launch so it is never later
  than the kill. No token ceiling is enforced (2.5 is not built), so no `tokens` is written. The
  baseline's scope carries no budget and stays byte-identical to earlier grids'.

### Every text change the model can see (confound risk)

These move together, so a trial cannot attribute an effect to one of them.

1. **`methodologyBlock` (system prompt, cached).** Removed: "Before finishing, briefly note what you
   did not get to and would investigate with more time." Added in its place: "The engagement's
   state persists: the ledger is where the next session starts, so there is no need to stop and
   ask leave to continue the work you were given. Before finishing, `record kind=settle`
   (finished, paused or blocked, with a note): pired computes what remains from the ledger, so the
   note need only say what the ledger cannot." Kept verbatim: "Covering the floor is the minimum
   bar; the ceiling is the creative work in phase 1."
2. **`record` description.** A new kind line: "- settle: outcome[finished|paused|blocked] (+note) —
   where this session leaves the engagement: finished (the work you were given is done), paused
   (work remains that you could still do) or blocked (what remains needs something only the
   operator can give). pired computes what remains from the ledger — open test cases, unmapped
   areas, unchallenged findings, inconclusive hypotheses, open blockers, budget spent — and records
   it with your note. It does not end the session."
3. **`record` schema.** `kind` gains `settle`; `outcome`'s enum gains `finished|paused|blocked` and
   a description naming which values go with which kind; a new `note` property ("For kind=settle:
   what you would say about where the session leaves the work."). The delete refusal names settle.
   Two new refusals the model can read: a settle from anyone but the lead ("record settle: only
   the lead session settles, and this call is from <author>. Hand back to the lead with what you
   found; the lead settles."), and a settle word as a hypothesis outcome ("record hypothesis:
   'outcome' must be one of proposed, testing, confirmed, refuted, inconclusive; "<value>" is not
   a hypothesis outcome.").
4. **`recall` description.** `status` is described as including "the areas, the budget when one is
   set, and the last settle".
5. **Tail block (per request, uncached).** The budget line in its four wordings (only with a scope
   budget): under 80%, "Budget: 12 of 45 min used, 33 left · 6.1M of 20M tokens used, 13.9M
   left."; from 80%, the same numbers then "— a ceiling, not a target. N% is used: record what is
   established."; at the ceiling, "— a ceiling, not a target. The ceiling is reached: settle
   (`record kind=settle`), which records what remains for the next session."; at the ceiling after
   a standing settle, "— a ceiling, not a target. The ceiling is reached; settled: <outcome>."
   The areas line: "Areas: N from the recorded surface, M settled. Not settled: <dir> (<status>[,
   K finding(s)]), … (+N more). Source directories with no recorded surface: …" (only once
   surface is recorded; the unmapped clause only once a file in the tree is).
6. **Tool output.** `recall status` gains `budget`, `settled` and `areas` lines; the settle reply.

There is no "unattended" statement (plan 3.2), and ADR-012's ambiguity rule is unchanged: the
persistence sentence covers "the work you were given", not a request that is unclear.

### Alternatives rejected

- **The budget in the system prompt.** It changes every request and would break the cached prefix;
  the tail block is already rebuilt per request after it.
- **Turns as a budget unit.** Nobody buys turns, and a turn's cost varies with context size.
- **Taking the caller's remainder.** A model that could write its remainder could write it empty.
- **Refusing a settle while work remains.** A gate on stopping is a step script by another name;
  the list is information and the decision stays the reviewer's.
- **Ranking areas, or showing the largest first.** Choosing what to look at next is the reviewer's
  call; areas come in path order, and the bounded line filters by status only.
- **Grouping tuned to the corpus's repositories.** The corpus is temporary; the rule is fixed on
  synthetic trees in `core/areas.test.ts` and `extensions/lib/source-dirs.test.ts`.
- **Stating a token ceiling in the benchmark now.** None is enforced, so none is stated.

### Measurement

As designed (§3.2 *Measurement*), pre-registered in 4.2: isolate with a single-agent pair
(candidate-solo against the baseline, or candidate-solo with and without 3.2). It should lower
Luna's offered-to-continue rate as read by the text test, keep true positives non-inferior, and
move cost (median per-pair log ratio) in a direction stated two-sided in advance. It is falsified
if the rate does not fall by the pre-registered margin, cost rises with true positives flat,
used/ceiling clusters near 1.0 (the budget read as a target), or GLM or DeepSeek start hitting
time limits more often.

### Risks and limits

- **The budget read as a target.** The line says "a ceiling, not a target"; used/ceiling near 1.0 in
  the trial falsifies the change.
- **The minutes clock.** Without a `deadline`, pired counts from `session_start`, which trails the
  host's own timer by its startup time; the benchmark writes a `deadline` so the two agree, and it
  is computed before launch, so it is never later than the kill.
- **Detached workers' spend after detach is not counted.** pi-subagents' foreground-complete event
  carries no usage. In the benchmark the harness's own token count is the authority.
- **Settle adoption varies by model.** Some may settle as a ritual; "the last settle not followed
  by work" handles that in the classifier, and settles are tallied per arm apart from the headline.
- **"Superseded" reads the creator's `by`.** See the Decision; the approximation holds while the
  benchmark runs the scribe off.
- **Area quality depends on repository layout**, and on the model recording `file` on its surface.
- **The baseline's scope is unchanged**, byte for byte; only the candidate's carries `budget`.
